# FoodRescue — Team Roles and Responsibilities

## 1. Team Overview

The FoodRescue project follows the Agile Scrum methodology. The team consists of four members, with each member assigned specific responsibilities to support planning, development, testing, and delivery.

## 2. Team Members and Roles

| Team Member | Role | Responsibilities |
|---|---|---|
| Aash | Scrum Master | Organizes Scrum meetings, tracks sprint progress, coordinates team members, identifies blockers, and ensures the team follows Agile practices. |
| Koushik | Backend Developer | Develops Flask backend logic, implements application routes and APIs, handles authentication and donation workflows, and integrates the backend with MySQL. |
| Sahithi | Frontend Developer | Designs and develops the user interface using HTML, CSS, JavaScript, and Bootstrap. Implements pages for restaurants, NGOs, food listings, and donation requests. |
| Sujay | Database and Testing | Designs the MySQL database and tables, manages data relationships, prepares test cases, tests application features, identifies bugs, and verifies fixes. |

## 3. Detailed Responsibilities

### 3.1 Scrum Master — Aash
- Conducts sprint planning, daily Scrum discussions, sprint reviews, and retrospectives.
- Maintains the sprint schedule and monitors task completion.
- Helps resolve blockers and improves team communication.
- Ensures the team follows the agreed project scope and Scrum workflow.
- Coordinates project documentation and demonstration preparation.

### 3.2 Backend Developer — Koushik
- Sets up the Python Flask backend.
- Implements registration, login, and role-based access.
- Develops APIs and routes for food listings and donation requests.
- Implements request acceptance, rejection, and pickup-status updates.
- Connects backend functionality to the MySQL database.
- Handles server-side validation and error handling.

### 3.3 Frontend Developer — Sahithi
- Creates responsive web pages using HTML, CSS, JavaScript, and Bootstrap.
- Designs the home page, login and registration pages, and dashboards.
- Develops the food listing and browsing interface.
- Creates forms for adding food listings and submitting donation requests.
- Displays donation statuses and history clearly.
- Integrates the frontend with backend APIs.

### 3.4 Database and Testing — Sujay
- Identifies the data entities and designs the database schema.
- Creates tables for users, food listings, donation requests, and related records.
- Defines primary keys, foreign keys, and necessary constraints.
- Tests registration, login, food listing, donation requests, and pickup workflows.
- Records test results and reports defects to the relevant team member.
- Retests corrected features and supports integration testing.

## 4. Shared Responsibilities

All team members are responsible for:
- Participating in sprint planning and progress discussions.
- Updating task status and communicating blockers.
- Reviewing and testing integrated features.
- Maintaining code using Git and GitHub.
- Contributing to documentation and the final project demonstration.
- Ensuring the application meets the agreed requirements.

## 5. Scrum Activities

| Scrum Activity | Purpose |
|---|---|
| Sprint Planning | Selects backlog items and defines the sprint goal. |
| Daily Scrum | Reviews progress, next steps, and blockers. |
| Sprint Review | Demonstrates completed features and collects feedback. |
| Sprint Retrospective | Identifies what went well and what should improve. |
| Backlog Refinement | Clarifies and prioritizes upcoming tasks. |

## 6. Communication and Collaboration

The team will coordinate through regular discussions and use GitHub to maintain source code, track changes, and organize project documentation. Tasks will be assigned according to the sprint backlog, while members will collaborate when features require frontend, backend, database, or testing integration.

## 7. Expected Outcome

Clearly defined roles help distribute work, improve accountability, reduce development conflicts, and support the timely delivery of the FoodRescue minimum viable product.
